ABYSSAL / HOSTED DEMO WORKFLOW

One transparent turn: commit, exchange, reveal, learn

A public player controls a browser board. The contained Node service validates game commands, commits an AI target before the player fires, and stores only anonymous board-coordinate outcomes in ephemeral local vector memory.

01 · PLACE

Deploy five ships

Client-side geometry previews and validates a standard 17-cell fleet.

  • Keyboard rotation + visible coordinates
  • No account, upload, or identity record
02 · COMMIT

Choose and seal target

Hunt rules and ruvector recall rank eligible cells before the player shot.

  • Random nonce + SHA-256 commitment
  • Target location stays hidden
03 · FIRE

Validate player shot

Bounded JSON request resolves one player impact against a server-owned enemy board.

  • Enemy geometry stays reveal-gated
  • Duplicate and invalid shots rejected
04 · REVEAL

Resolve return fire

The precommitted target and nonce are revealed after the player action.

  • Browser recomputes commitment hash
  • Telemetry exposes confidence, not secrets
05 · LEARN

Record an outcome

Finished games append coordinate-only placement and shot episodes for later similarity recall.

  • Ephemeral container filesystem only
  • No public export or reset endpoint
Data boundaryOnly anonymous board positions and hit outcomes are retained while this container is alive.
Service boundaryThe browser uses the game host only; there is no model provider, identity service, database, or browser secret.
Integrity boundaryCommit-and-reveal proves that the AI target did not change after the player shot was received.
