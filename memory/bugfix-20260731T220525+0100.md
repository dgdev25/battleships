# Bugfix record — repeat-play sluggishness and battle feedback

## Report

The game had previously made the machine sluggish after one use. The requested
feature pass also needed a missile whistle, distinct water/explosion impacts,
visible blasts, recognizable hulls, and adjustable exchange pacing.

## Root cause

The strongest freeze causes were in the immediately preceding client runtime:
infinite non-composited wreck `box-shadow` repaints, an invisible rotating radar
surface, regenerated noise buffers, repeated DOM rebuilding, and retained
finished server sessions. The current baseline already contained targeted fixes
for those paths. A real Chrome trace confirmed no continuing heap climb: after
48 full exchanges, transient effect nodes were zero and used heap was 3.16 MB.

## Dependency map summary

`app.js` sequences the exchange and lifecycle; `sfx.js` owns one lazy audio
graph; `fx.js` owns bounded effect nodes; `ships.js` maps server/setup geometry
to overlays; CSS supplies finite compositor-friendly motion; `server.mjs`
reveal-gates hull geometry and releases completed games; ruvector intentionally
grows only with learned episodes.

## Fix and enhancement

- Added a public-domain recorded explosion with Web Audio crack, sub-bass,
  debris, and a procedural fallback. Sources explicitly disconnect on end.
- Added descending multi-voice missile whistles and layered water splashes.
- Added finite fireballs, smoke clouds, shockwave, sparks, water plume/droplets,
  sinking wreck treatment, and hit/impact timing that does not reveal early.
- Added shaped carrier, battleship, cruiser, submarine, and destroyer overlays
  for setup/live play; enemy geometry crosses the wire only at game-over.
- Added a persistent 0.2–2.5 second return-fire tempo slider.
- Added regression/game/geometry tests and corrected the page landmark/ARIA
  structure discovered by Lighthouse.

## Verification and lesson

- 12/12 Node tests passed; every JS/MJS file passed syntax checking; diff check
  was clean; audio served as `audio/ogg` with HTTP 200.
- Chrome completed a 48-shot game with zero leftover `.fx` nodes. Three further
  server games completed and correctly reveal-gated enemy hulls. Adding 582
  vector episodes increased server RSS by about 7.8 MB, consistent with the
  intended learning index rather than retained games.
- Mobile Lighthouse scored 100 accessibility, best practices, SEO, and agentic
  browsing; the final console had no errors, warnings, or issues.

The important pattern is that GPU/paint churn can feel like a memory leak even
when the JavaScript heap is stable. Every persistent animation and audio graph
needs an explicit bounded-lifetime or visibility policy.

No commit was created because the working tree contained pre-existing user
edits in the same client files; committing would claim those changes without
explicit authorization.
